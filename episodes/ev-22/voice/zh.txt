做 agent 评测，要掌握哪些背景知识？
这份工作横跨数据、统计和工程。
所以要学的知识，可以归成四类。
我们拿一个退款客服 agent 来举例。
先说数据与标注，因为考题都来自数据。
你要会从线上对话里抽样。
只随手抽，抽到的大多是普通的小额退款。
所以要按金额和问题类型，分组来抽。
这样五百元以上这种少见的情况，也能抽到。
抽出来的对话，还要有人标对错。
你得会让几个人标同一批，再算一致率。
两个人意见不一样，往往说明规则没写清。
比如顾客还在生气，到底算不算解决了？
再说判分与统计，因为分数要算得对、读得懂。
钱有没有退，用代码查数据库就够了。
回复的语气好不好，就要交给模型裁判。
所以你要会写评分细则，也要懂裁判的偏见。
统计也少不了，因为 agent 每次跑的结果都不同。
比如新版本，在一百道题里多过了两道。
这很可能只是波动，算误差范围才知道。
更好的办法，是在同一道题上配对比新旧。
题目的难易被抵消了，差别更容易看出来。
然后是工程与环境，评测要靠它跑起来。
你要会给 agent 打记录，记下每一步做了什么。
你还要会搭沙箱，用模拟的退款工具。
这样跑一千遍，也不会真的退出一分钱。
还要把评测接进 C I。
C I 就是每次改代码，都会自动跑的检查。
成本也得会算，因为每跑一遍都要花钱。
模型裁判判一次分，也是一次模型调用。
最后是行业生态，因为不用什么都自己造。
你要读懂公开的基准，知道它们测的是什么。
榜单比的是模型，放在统一的框架里跑。
你的评测，测的是模型加提示词、工具和规则。
还要知道有哪些工具，大团队是怎么做的。
所以说，这四类知识，各管一件事。
数据和标注，让你出得了好题。
判分和统计，让你信得过分数。
工程和环境，让评测跑得起来。
行业生态，让你知道有什么可以直接用。

行业里都用什么工具，做 agent 评测。
