这期来实战，给退款 agent 搭一个可重置的沙箱。
沙箱，就是一个隔离起来的小环境。
agent 在里面怎么折腾，都碰不到真实数据，
用完就扔，下次再起一个干净的。
我们用 Inspect 来搭，这是个开源的评测框架，
由英国的 A I 安全研究所开发。
整个沙箱，一共由四样东西组成。
先写模拟工具，查订单、退款和发邮件，
都写成普通的函数，只读写沙箱里的数据库，
不会去连真实的支付和邮件系统。
在 Inspect 里，工具出错可以抛 tool error，
这条报错，会交回给模型自己去处理。
正好可以用来考，它遇到故障会怎么办。
再准备预置数据，每道题都带着自己的订单。
比如一副十天前买的耳机，三百元，
再放一单别人买的，用来考它核不核实买家。
Inspect 的每道题，都可以带上一些文件，
再加上一段初始化用的脚本。
沙箱一启动，就把这份订单写进数据库。
再说重置，Inspect 的沙箱可以用 Docker 来跑。
Docker 会把整个运行环境，装进一个容器里。
Inspect 给每道题，单独起一个沙箱，
题和题之间，什么东西都不共享。
整套题跑完，它会把这些容器自动清理掉。
所以重置不用我们自己写，下次又是全新的。
另外，它默认生成的容器是断网的，
agent 想连外面的真实服务，也连不上。
最后一样，是再接上一个模拟顾客。
用另一个模型来演，照着剧本里写的身份、
目标、隐藏信息和底线，跟 agent 一轮轮地聊。
聊完之后，判分器进沙箱查数据库。
该退的钱退了没有，金额对不对，
别人的那一单，有没有被它动过。
所以说，一个可重置的沙箱，就是这四样东西。
模拟工具，保证碰不到真实系统。
预置数据，保证每次的起点都一样。
模拟顾客，让多轮对话能自动地跑。
每道题一个新容器，让每次试跑互不干扰。
搭好以后，同一道题想跑多少遍都可以。

整体评和拆开评，什么时候要拆。
