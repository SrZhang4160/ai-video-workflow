agent 框架自带的评测，能帮你做些什么？
很多团队用现成的框架来搭 agent，
框架的作者顺手提供了一套评测命令。
你写好 agent，在同一个框架里就能考它。
单独的评测工具不挑框架，但要多接一层。
先看谷歌的 A D K，它自带一条 A D K eval 命令。
考题写在一个评测集文件里，
每道题写顾客说的话，和期望调用的工具。
比如退款这道题，期望先查订单，再退款。
判分时，它会拿 agent 实际调的工具来对比。
对比有三种严格程度，默认要求一模一样，
多调一个、少调一个，都算不对。
宽松一点的，只要求这几步按顺序出现。
最宽松的，连顺序都不管，都出现就行。
最后的回复，会和标准答案比用词的重合。
A D K 还能让一个模型扮演顾客，陪 agent 聊。
你只写下开场白，和这位顾客想达成的目标，
后面每一句，都由模型临场编出来。
这样就能考多轮对话，不用你一句句写死。
再看 OpenAI 的 Agents S D K，它默认开着追踪。
追踪就是把 agent 每一步都记成一条记录，
模型调用和工具调用，都能在控制台里看到。
在一条记录上，还能配一个判分器来打分，
比如检查它退款之前，有没有先查订单。
这件事叫 trace grading，就是给整条记录判分。
OpenAI 自己托管的评测平台，就别再用了。
官方公告，它在二〇二六年十一月三十日关停。
官方建议迁到 promptfoo，考题记得导出来。
红队工具不考做事，考它会不会被人骗。
红队，就是故意扮成攻击者，去找它的漏洞。
微软的 PyRIT，能对 agent 发起多轮的攻击，
一轮轮试探，看能不能骗它退别人的订单。
英伟达的 garak，是一个漏洞扫描器。
它批量发出提示注入、越狱这类攻击，
再用检测器判断，哪些回复中招了。
promptfoo 的红队功能，按漏洞类型自动出题。
比如有一类专门考越权，会假装成客服。
它向 agent 要别人的订单，看它给不给。
所以说，框架自带的评测接起来最省事，
但只能考用这个框架搭的 agent。

这么多工具，到底该怎么选。
