DeepEval、openevals 和 Ragas，分别适合谁？
这三个都是开源的评测工具，都能用 Python。
我们拿退款客服 agent 当例子来比一比。
它会查订单、退款，再给顾客发邮件。
三个工具最大的差别，在于你怎么写评测。
先说 DeepEval，它的写法很像 py test。
py test 是 Python 里写单元测试的常用工具。
你写一个测试函数，里面放一道测试用例。
用例里写顾客的话，和 agent 调过的工具。
再挑几个现成的指标，最后断言分数过线。
它给 agent 专门准备了现成的指标。
比如工具正确性，对比调用的和期望的工具。
它跳过查订单直接退款，这项分就会掉。
还有任务完成度，由模型读整条记录来判。
它的好处是，会写单元测试就会用它。
弱点是很多指标靠模型打分，要验证准不准。
再说 LangChain 团队做的 openevals 和 agentevals。
这两个库只做一件事，提供现成的评估器。
openevals 里有写好的裁判提示词。
比如判回答对不对、有没有编造内容。
你挑一个，交给一个模型，它就能当裁判打分。
agentevals 专门比对 agent 走过的步骤。
你先写好标准答案，也就是该调哪些工具。
严格模式要求调用和顺序都一模一样。
无序模式只看调用对不对，不管先后。
子集模式不许多调，超集模式允许多调。
弱点是只有评估器，题库和运行要自己管。
最后是 Ragas，它本身就是一个指标库。
它起家于 rag，就是先查资料再回答的系统。
比如忠实度，看回答是不是都有资料撑着。
后来它加了 agent 指标，比如工具调用准确率。
默认要求工具、参数和顺序全都对上。
还有目标准确率，判断顾客的目的达成没有。
它适合想要现成指标的团队，尤其是做 rag 的。
弱点是 agent 的记录，得先转成它的格式。
所以说，想像写单元测试一样测，用 DeepEval。
要现成裁判、比对步骤，用 LangChain 这两个库。
只想要一套现成的指标，就用 Ragas。
