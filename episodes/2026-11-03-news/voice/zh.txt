你跟 AI 聊天，它其实不记得上一句。
每说一句，程序都要把聊天记录，从头再发一遍。
就像打客服电话，每次都要从头讲一遍。
对话越久，要讲的越多，它开口就越慢。
昨天，Claude 的 API 上线了一个新功能，
叫消息线程，相当于客服给你建了个档案。
第一次，你把来龙去脉全讲一遍；
之后只说新的那一句，再报上档案号。
这个档案号，就是上一条回复的编号。
官方称：50 万到 100 万 token 的超长请求，
等第一个字的时间，中位数少了约 35%。
这是 Claude Code 里测的，大部分用户已默认开启。
快在哪？以前每次整段对话都要再传、再处理；
现在对话留在服务器上，主要只处理新的一句。
但模型每一次，还是要把整段对话读一遍，
所以计费的用量、价格和限额都不变。
规矩有几条：线程五分钟没请求就过期，
过期再接会返回 404，只能从头再发一遍。
只能往后加，每个回复编号只能接一次；
流式输出时，要等回复完全结束再接下一轮。
而且没有接口能列出、读取或删除线程。
数据方面：线程加密放内存里，不写进硬盘，
最晚 1 小时删除，但不支持零数据保留和 HIPAA。
批量处理、token 计数、压缩等，都不能一起用。
我的看法：这是给要跑很久的 agent 准备的。
短对话省不了多少；超长的编程 agent 最划算。
聊天记录你自己也要存一份，过期了好从头再发。
一句话：档案留在服务器上，你只说新的；
超长对话回复更快，价格不变。

以及会不会补上查看、删除线程的接口。
