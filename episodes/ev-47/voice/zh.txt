这期来讲，怎么让大模型扮演顾客，来考 agent。
退款客服 agent，要跟顾客来回聊好几轮。
它会追问订单号，顾客回答了，它再去查。
如果一道题，只写了顾客说的第一句话，
后面的追问就没人回答，题也跑不下去。
找真人来陪聊，又太慢太贵，没法每天跑。
所以我们让另一个大模型来扮演顾客，
这样的角色，就叫模拟用户。
它和 agent 一句接一句地对话下去，
直到问题解决，或者聊不下去为止。
要让它演得像，就得在提示词里交代清楚。
先是身份，比如一位上周买了耳机的顾客，
说话很简短，而且还有点着急。
再是目标，他想要把钱退回来。
然后是只有他知道的信息，比如订单号，
规定只有 agent 问起来，他才会说出来。
这样才考得出，agent 会不会主动核实。
最后是底线，比如不接受换货，只要退钱，
也不能编出剧本里没有的信息。
行业里，tau bench 就是这样考客服 agent 的。
它是 Sierra 的研究团队做的，
最早有零售和航空这两个业务场景。
agent 手里有查询和修改订单的工具，
同时还要遵守一份写好的业务规则。
顾客由大模型来扮演，照着任务说明提要求。
每道题的说明都写得很细，
保证按照规则，只有一种正确的结果。
判分的时候，不看 agent 话说得好不好听，
而是看对话结束时，数据库变成了什么样。
把它和标准答案里的数据库比一比，
两边完全一样，这道题才算通过。
另外，该告诉顾客的关键信息，也得说到。
换到退款 agent 上，就是去查这一单退了没有，
退了多少钱，有没有退给不该退的人。
所以说，模拟用户就是让模型照剧本当顾客。
有了它，多轮对话也能自动地反复跑。
剧本里写清身份、目标、隐藏信息和底线，
判分时，再去看数据库最后的状态。
不过，模型演的顾客和真人并不完全一样。

为什么模拟出来的顾客，太“好说话”。
