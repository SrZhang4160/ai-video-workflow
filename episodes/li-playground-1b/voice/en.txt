Now the full picture: after a code change, how do all four get updated and go live?
Every change I make goes up as a pull request on GitHub.
As soon as it's opened, GitHub Actions runs checks automatically.
The checks are: type checks and unit tests;
smoke tests, a quick run through the main flows to catch anything obviously broken;
building the service's Docker image and actually starting it;
and checking that the Terraform config is valid.
Only when all of those pass can the code be merged.
Merging doesn't put it live right away. Going live is one more step.
First, the new versions get built: the service's Docker image, and the sandbox template.
The template is the system a sandbox starts from, with everything preinstalled.
Right now I build both of these myself.
Then I update the version numbers in Terraform.
Terraform first makes a plan that lists exactly what will change.
Only after I review and approve it does it run:
the service switches to the new image, any entry changes go out too,
and new sandboxes start from the new template.
So the whole path is: automatic checks on every P R, a human approval,
and then Terraform updates the entry, the service and the sandbox together.
