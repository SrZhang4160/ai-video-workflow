This episode turns evals into an improvement loop.
This loop uses all six parts of evaluation.
Say a case fails. What should you do next?
Say the "broken headphones" case fails.
Most people guess a cause and edit the prompt.
Because the score says it failed, not why.
Guess wrong, and you may break something else.
So don't change anything yet; read the transcript.
A transcript records every step the agent took:
which tool it called, with what arguments,
what came back, and what it told the customer.
Step by step, you find what really failed.
Sometimes you find the agent did nothing wrong.
The eval itself is wrong, say its expected answer:
a forty-day-old order, yet the case expects a refund.
Policy says refuse. It refused, and was marked wrong.
Or the mock order-lookup tool itself is broken,
returning an empty order, so it finds nothing.
Then you fix the eval, not the agent.
Otherwise you'd break good behavior for a bad case.
If the agent really skipped the owner check,
don't fix it yet. First add a case
that checks it verified the owner before refunding.
Run it. Right now, the new case should fail.
If it fails, the case really captures the problem.
Only then fix the agent, say with a new prompt rule.
Rerun. The new case must pass, and no old one may regress.
The new case stays and runs on every change.
Finally, let's put all twenty episodes together.
Building evals comes down to these six blocks.
The first is test cases, drawn from real failures.
The second is the environment, a safe sandbox.
The third is grading, which checks the real state.
The fourth is metrics, tracking success rate and cost.
The fifth is process, which runs evals on every change.
The sixth is pitfalls, a reminder not to chase the score.
Today's loop is simple: write the case first, then fix,
then check again that nothing regressed.
Each loop adds one more real case to your eval set,
closer to real traffic, and the agent gets steadier.
