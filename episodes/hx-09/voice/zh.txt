MCP、harness 和 function calling，
它们到底是什么关系？
很多人以为，模型会自己去调 MCP 服务。
其实模型什么都不执行，它只会输出文字。
function calling 是模型的一种能力：
给它一组工具说明，
它就能输出一个结构化的工具调用，
也就是 tool call：工具名加参数。
比如：查天气，城市波士顿，日期周六。
真正执行这个调用的，是 harness。
harness 是包在模型外面、替它干活的程序。
它解析 tool call，找到查天气这个工具，
执行它，再把结果发回给模型。
模型看到结果，再决定下一步。
那 MCP 在哪儿？在工具的背后。
harness 通过 MCP client 连上天气 server，
把它的工具包装成自己的一个工具。
对模型来说，这就是又一个工具，
分不出是本地工具，还是 MCP 工具。
没有 MCP 也能接，只是要逐个写适配器。
本质：模型只写调用，harness 负责执行，
MCP 只是工具背后的一种接法。
