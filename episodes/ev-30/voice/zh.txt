这期我们动手，把退款评测从头跑通。
用的是一个开源的评测框架，叫 Inspect，
题目、agent 和判分，都用 Python 来写。
先跟一道题走到分数，再跑整套读结果。
先写题目，在 Inspect 里叫做一个 sample。
它的 input，就是顾客说的那句话，
比如“我上周买的耳机坏了，想退款”。
它的 target，写的是我们期望的结果，
也就是这一单应该退款三百元。
光有这两样还不够，因为 agent 要查订单。
所以我们再给这道题，配一份假的订单库。
库里这一单是七天前买的，花了三百元，
而且确实是这位顾客本人下的单。
这份文件会被复制进这道题的沙箱里。
接着来看 solver，也就是被测的这个 agent。
这里我们直接用 Inspect 自带的 react agent，
把查订单、退款、发邮件三个工具交给它。
这三个工具，只读写沙箱里的假订单库。
跑起来以后，它先读顾客说的话，
再去查订单，确认是本人、在三十天内，
然后调用退款工具，最后发一封邮件。
等 agent 停下来以后，就轮到 scorer 来判分。
我们的判分器，不看它嘴上说了什么，
而是直接打开沙箱里的那份订单库，
查这单退没退，金额是不是三百元。
两样都对，就算通过，否则就算不通过。
它还会写一句说明，讲清楚为什么这么判。
一道题能跑通，就把整套题一起跑。
只要一条 inspect eval 命令，整套题就能跑完。
跑完先看准确率，也就是通过的比例。
可光看一个数，你不知道它错在哪里。
所以我们再用 inspect view 把日志打开，
按分数筛选，只留下没通过的题。
比如有一单六百元，agent 直接就退了。
点开它的消息记录，一步一步往下看，
就会发现，它根本没把这单转给人审批。
这样你就知道，该去补强哪一条规则了。
所以说，跑通评测，先写好题，配上假数据。
再让 agent 在沙箱里做，判分器去查结果。
最后打开日志，读那些没通过的题。
