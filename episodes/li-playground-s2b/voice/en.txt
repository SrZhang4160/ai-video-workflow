Now the sandbox side, starting with the hardest question:
where does the user's code run?
The requirements: strong isolation, Docker inside,
a fast start, and nothing left running when idle.
Option one, containers we run ourselves.
Easy, but containers share the host's kernel,
the lowest layer of the operating system,
so they're not a safe wall between strangers.
And Docker inside a container means a privileged container,
which hands over most of the host.
Option two, Kubernetes with gee visor,
which gives each container its own simulated kernel.
Strong isolation, but I'd have to run a cluster myself.
Option three, a managed sandbox.
Daytona fits long-lived workspaces.
Modal is mainly for Python and GPU jobs.
E two B is built for AI agents that run code.
Each sandbox is its own Firecracker micro V M, with its own kernel.
It starts from a prebuilt template, runs Docker inside,
and destroys itself when time is up.
That meets all four requirements, so I chose E two B.
The cost: one more vendor, billed by the second.
So it sits behind a thin interface: create, find and destroy.
Locally, the same three run on Docker.
Next, the editor. The requirement: it should feel like a real product.
Option one, a page with a few buttons.
My first version was this, and it looked like a demo.
Option two, a terminal in the browser.
Light, but most people don't want to stare at a command line.
Option three, code server: open-source V S Code in the browser,
with real files, a real terminal, and the AI assistant as an extension.
That's what I chose.
The cost: a big download the first time it opens.
And every session has its own subdomain,
so the browser can't reuse that download across sessions.
Last, the AI calls.
The requirement: the AI in the sandbox can call the model,
but no real key ever enters the sandbox.
Option one, put an API key in the sandbox.
But anything in there can be printed out, by the user or by the AI.
Option two, pass in the user's own login token.
Even worse: with it, you can do anything the user can.
Option three, a token that only works for this one session.
A gateway in my service checks it,
swaps it for the real credential on the server side,
and forwards only allowed calls.
That's what I chose. The cost: one more hop on every model call.
