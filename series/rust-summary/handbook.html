① 基础语法

学过 Python、JavaScript 的话，这一层很快。重点是两件事：变量默认不可变；几乎一切都是表达式。

01

Rust 知识全景：五块知识怎么搭

Rust 的知识是一层层往上搭的：基础语法 → 所有权 → 数据建模 → 工程化 → 进阶。所有权最难，也最重要。
  • 基础语法：变量、函数、条件、循环。
  • 所有权：一个值只有一个主人，想用就借。不用垃圾回收，内存也安全。
  • 数据建模：struct 描述数据，enum 表示几种可能，trait 定义共同行为。
  • 工程化：Cargo 管项目，Result 处理错误，cargo test 跑测试。
  • 进阶：迭代器、闭包、智能指针、并发和异步。
建议：基础快速过，所有权一定要吃透。后面每一课遇到的编译错误，十有八九和所有权、借用有关。
02

变量：let、mut 和 shadowing

变量默认不能改；要改值加 mut；要换类型用 shadowing（再写一次 let）。
let x = 5;
// x = 6;               // 编译不过：E0384，不能给不可变变量赋两次值
let mut y = 1;
y += 1;                 // 加了 mut，可以改
let s = "42";           // &str
let s: i32 = s.parse().unwrap();  // shadowing：同名新变量，类型换成 i32
  • 默认不可变是故意的：一眼就能看出哪些值会变，编译期就能拦住误改。
  • mut 只能改值，不能改类型；shadowing 是新变量，可以换类型。
03

基本类型：整数、浮点、bool、char、元组、数组

标量是单个值（整数、浮点、bool、char）；复合类型里，元组装不同类型，数组装同一种类型、长度固定。
let a: u8 = 255;           // u = 无符号，8 = 位数；整数默认 i32
let b = 3.0;               // 浮点默认 f64
let c = true;              // bool：true / false
let d = '中';              // char 用单引号，一个 Unicode 字符
let t: (i32, f64, char) = (1, 2.0, 'a');
let first = t.0;           // 元组用 .下标
let arr: [i32; 3] = [1, 2, 3];
let x = arr[0];            // 数组用 [下标]，长度写在类型里
坑：整数和浮点不能直接相加（1 + 2.0 报 E0277），Rust 不会偷偷转换，要自己写 as f64。
考考你：let x = 3.0; x 是 f32 还是 f64？ 答案：f64，浮点数不写类型时默认 f64。
04

函数与表达式：最后一行不加分号就是返回值

语句只做事、不产生值；表达式会算出一个值。函数体最后一行不加分号，它的值就是返回值。
fn add(a: i32, b: i32) -> i32 {   // 参数必须标类型，-> 后写返回类型
    a + b                          // 没有分号：这是返回值
}

let y = {                          // 代码块也是表达式
    let x = 3;
    x + 1                          // y = 4
};
  • 加上分号，表达式就变成语句，值被丢掉，只剩空元组 ()。
  • 想提前返回，才用 return。
考考你：fn five() -> i32 { 5; } 能编译吗？ 答案：不能。5; 是语句，函数实际返回 ()，和 i32 对不上（E0308）。去掉分号就好。
05

控制流：if 是表达式，loop / while / for

if 是表达式，能直接赋值；一直转用 loop（break 可以带值），按条件用 while，遍历用 for。
let kind = if n % 2 == 0 { "even" } else { "odd" };  // 不需要三元运算符

let mut c = 0;
let r = loop {
    c += 1;
    if c == 10 { break c * 2; }    // 只有 loop 的 break 能带值出来
};
while c > 0 { c -= 1; }
for i in 0..3 { println!("{i}"); } // 0, 1, 2（不含 3）
考考你：let n = if true { 1 } else { "one" }; 能编译吗？ 答案：不能。两个分支必须是同一种类型：1 是整数，"one" 是 &str（E0308）。

② 所有权与借用

Rust 不用垃圾回收、也不用手动释放内存，靠的就是这一层：编译时就把内存的账算清楚。

06

所有权的三条规则

每个值都有一个主人；同一时刻只有一个主人；主人离开作用域，值被自动清理。
let s1 = String::from("hi");
let s2 = s1;          // 所有权交给 s2
// println!("{s1}");  // 编译不过：E0382 borrow of moved value
}                     // s2 离开作用域，内存自动释放（编译器插入 drop）
方式谁来释放代价
手动释放（C）程序员容易漏放、重复放
垃圾回收（Java、Go）运行时运行时额外开销
所有权（Rust）编译器编译时检查，运行时零开销
07

Move、Clone、Copy 有什么区别

Move 搬走所有权，旧变量作废；Clone 手动完整复制一份，可能很贵；Copy 自动复制，旧变量照样能用。
let s1 = String::from("hi");
let s2 = s1.clone();   // 堆上的数据完整复制一份，s1、s2 都能用
let a = 5;
let b = a;             // i32 实现了 Copy：a 照样能用
  • Move 和 Copy 底层一样，都是复制栈上的字节；区别只在旧变量还能不能用。
  • 整数、浮点、bool、char 是 Copy；String、Vec 管着堆内存，不是 Copy。
  • 自定义类型可以 #[derive(Clone, Copy)]（前提是字段都是 Copy）。
考考你：let a = 5; let b = a; 之后再打印 a，能编译吗？ 答案：能。i32 是 Copy，换成 String 就不行。
08

借用：& 和 &mut 的规则

同一时刻，要么很多个 &（只读），要么只有一个 &mut（能改）。不能一边读一边改。
fn len(s: &String) -> usize { s.len() }     // 只借来读，所有权不动
fn push_bang(s: &mut String) { s.push('!'); } // 借来改

let mut s = String::from("hi");   // 要可变借用，变量本身也得是 mut
let n = len(&s);
push_bang(&mut s);
let r = &s;
println!("{r}");    // r 最后一次使用，借用到这里就结束了
s.push('a');        // 所以这里可以改
  • 这条规则从根上避免了数据竞争。
  • 借用的范围到「最后一次使用」为止，不用等到大括号结束（NLL）。
考考你：let r = &s; s.push('a'); println!("{r}"); 能编译吗？ 答案：不能（E0502）。r 后面还要用，这时不能可变借用 s。把 println 挪到 push 前面就行。
09

String 和 &str：切片是什么

String 拥有自己的文字，放在堆上、能变长；&str 是字符串切片，只借来看一段（起点 + 长度）。
fn first_word(s: &str) -> &str {   // 参数写 &str 最通用
    s.split(' ').next().unwrap_or("")
}
let s = String::from("hello world");
let w = first_word(&s);            // &String 自动转成 &str
let lit = first_word("hi there");  // 字面量本身就是 &str
let part = &s[0..5];               // "hello"，按字节下标切
坑：切片按字节切。中文一个字 3 个字节，切到半个字会 panic。处理中文请用 .chars()。
考考你：let s = "hi"; s.push('!'); 能编译吗？ 答案：不能（E0599）。"hi" 是只读的 &str，没有 push。要改就用 let mut s = String::from("hi");

③ 数据建模

用 struct 描述「几样都有」的数据，用 enum 描述「几种里选一种」，再用 Option 把「可能没有」写进类型里。

10

struct + impl：给数据加方法

Rust 没有 class：struct 放数据，impl 放方法。第一个参数是 self 的叫方法（用 . 调用），没有的叫关联函数（用 :: 调用）。
struct Rect { w: u32, h: u32 }

impl Rect {
    fn new(w: u32, h: u32) -> Self { Rect { w, h } }  // 关联函数：Rect::new(3, 4)
    fn area(&self) -> u32 { self.w * self.h }       // &self：只读
    fn grow(&mut self) { self.w += 1; }             // &mut self：能改
}
let mut r = Rect::new(3, 4);
r.area();   // 12
  • &self 只读、&mut self 能改、self 拿走所有权，正好对应前几课的三种方式。
考考你：fn inc(&self) { self.n += 1; } 能编译吗？ 答案：不能（E0594）。&self 只读，要改就写 &mut self。
11

enum + match：穷尽所有情况

enum 列出所有可能；match 每种情况都得处理，漏了一种就编译不过。
enum Light { Red, Yellow, Green }

fn secs(l: Light) -> u32 {
    match l {                 // match 也是表达式
        Light::Red => 30,
        Light::Yellow => 3,
        Light::Green => 25,   // 少写一个分支：E0004 non-exhaustive
    }
}
坑：_ => 能兜住剩下的情况，但以后新加的情况也会被它悄悄吞掉，失去「漏写就报错」的保护。
考考你：enum Dir { Up, Down, Left }，match 里只写 Dir::Up 和 _，能编译吗？ 答案：能，_ 匹配了剩下的所有情况。
12

Option：Rust 为什么没有 null

Rust 没有空值，用 Option<T>（Some(值) 或 None）把「可能没有」写进类型。Option<i32> 不是 i32，不处理 None 就用不了。
fn plus_one(x: Option<i32>) -> i32 {
    match x {
        Some(n) => n + 1,
        None => 0,
    }
}
if let Some(n) = x { println!("{n}"); }  // 只关心有值的情况
let v = x.unwrap_or(0);                  // 给默认值
坑：x + 1（x 是 Option<i32>）编译不过（E0369）。unwrap() 遇到 None 会直接崩，正式代码少用。
考考你：let x: Option<i32> = Some(5); match 只写 Some(n)，能编译吗？ 答案：不能（E0004）。编译器只看类型不看值，漏了 None 就报错。

④ 错误处理与工程化

Rust 没有异常：错误也是一个值。Cargo 一个工具管完建项目、依赖、测试。

13

Result 和 ? 运算符：错误处理

Result<T, E>：成功是 Ok(值)，失败是 Err(错误)。match 就地处理，? 把错误交给上层，unwrap 只在确定不会错时用。
use std::num::ParseIntError;

fn parse_sum(a: &str, b: &str) -> Result<i32, ParseIntError> {
    let x: i32 = a.parse()?;   // 成功取值继续，失败直接 return Err
    let y: i32 = b.parse()?;
    Ok(x + y)
}
parse_sum("1", "2");   // Ok(3)
parse_sum("a", "2");   // Err(...)
  • 比起 Option，Result 还能说出失败的原因。连 main 都可以返回 Result。
考考你：fn f() -> i32 { let n: i32 = "7".parse()?; n } 能编译吗？ 答案：不能（E0277）。用 ? 的函数自己也得返回 Result（或 Option）。
14

Cargo：建项目、加依赖、跑测试

四个命令走完一个项目：cargo new 建项目、cargo run 运行、cargo add 加依赖、cargo test 跑测试。
$ cargo new hello      # 生成 Cargo.toml 和 src/main.rs
$ cd hello && cargo run
$ cargo add serde      # 写进 Cargo.toml，编译时从 crates.io 下载
$ cargo test

#[test]
fn adds() {
    assert_eq!(add(2, 2), 4);   // 不相等就 panic，测试失败
}
考考你：assert_eq!(2 + 2, 5); 跑 cargo test，结果是 ok 还是 FAILED？ 答案：FAILED，assert_eq! 不相等会 panic。

⑤ 抽象：trait、泛型、生命周期

trait 定义「能做什么」，泛型让一份代码用于多种类型，生命周期告诉编译器「引用能活多久」。三者都在编译期检查，没有运行时开销。

15

trait：定义共同行为

trait 是一份行为清单。给类型实现它，一个参数 &impl Trait 就能收下所有实现了它的类型。
trait Speak {
    fn speak(&self) -> String;                 // 只有签名：必须实现
    fn hello(&self) -> String {                // 默认实现：可以不写
        format!("I say {}", self.speak())
    }
}
struct Dog; struct Cat;
impl Speak for Dog { fn speak(&self) -> String { "woof".into() } }
impl Speak for Cat { fn speak(&self) -> String { "meow".into() } }

fn talk(x: &impl Speak) { println!("{}", x.speak()); }
talk(&Dog); talk(&Cat);   // 没实现 Speak 的类型传进来：编译报错
考考你：impl Speak for Dog {}（speak 没有默认实现）能编译吗？ 答案：不能（E0046），必须把 speak 写出来。
16

泛型：一份代码，多种类型

<T> 声明类型参数，trait 约束规定 T 能做什么。编译时按用到的类型各生成一份，跑起来和手写一样快。
fn largest<T: PartialOrd>(a: T, b: T) -> T {   // 不加约束，a > b 编译不过（E0369）
    if a > b { a } else { b }
}
largest(3, 7);        // 7，T = i32
largest("a", "b");    // "b"，T = &str

struct Pair<T> { a: T, b: T }   // Option<T>、Vec<T> 也都是泛型
  • 上一课的 &impl Speak 其实就是泛型 <T: Speak> 的简写。
考考你：fn show<T>(x: T) { println!("{}", x); } 能编译吗？ 答案：不能（E0277），T 不一定能打印。改成 T: std::fmt::Display。
17

生命周期入门：'a 到底在说什么

'a 不改变任何值活多久，它只是告诉编译器：返回的引用和哪个参数活得一样久，好让编译器检查不会出现悬垂引用。
// fn longest(x: &str, y: &str) -> &str   // E0106：返回的引用来自 x 还是 y？
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}

let r;
{
    let s = String::from("hi");
    r = &s;        // E0597：s 在这个大括号结束就没了
}
// println!("{r}"); // r 会指向已经释放的内存，所以编译器不让

struct Excerpt<'a> { part: &'a str }   // 结构体里存引用，也要标生命周期
  • 大多数时候不用写：编译器有「省略规则」，比如只有一个引用参数时，返回值自动跟它一样久。
  • 只有编译器推不出来（多个引用参数、返回引用、结构体存引用）时才需要写。
考考你：fn first(x: &str, n: usize) -> &str { &x[..n] } 能编译吗？ 答案：能。只有 x 一个引用参数，省略规则自动把返回值和 x 绑在一起，等于写了 <'a>。

⑥ 进阶与实战

把前面的知识拼起来：迭代器链处理数据，clap 做命令行，reqwest + serde 调网络 API。学完这三课，就能写出真正有用的小工具。

18

迭代器和闭包

闭包是能捕获周围变量的匿名函数 |x| x * k；迭代器用 map / filter 串成一条链，最后用 collect、sum 这类方法真正跑起来。
let v = vec![1, 2, 3, 4];
let k = 10;
let out: Vec<i32> = v.iter()
    .filter(|&&x| x % 2 == 0)   // 闭包当参数
    .map(|x| x * k)             // 捕获外面的 k
    .collect();                 // [20, 40]
let total: i32 = v.iter().sum();   // 10

let s = String::from("hi");
let own = move || println!("{s}");  // move：把 s 的所有权搬进闭包
  • 迭代器是惰性的：只写 map 不 collect，什么都不会执行（编译器会提示 unused）。
  • iter() 借元素（&T），iter_mut() 可变借用，into_iter() 拿走所有权。
  • 编译后和手写 for 循环一样快（零成本抽象）。
坑：let d: Vec<i32> = v.iter().map(|x| x * 2); 编译不过（E0308）：map 返回的是迭代器，不是 Vec，要加 .collect()。
考考你：v.iter().map(|x| println!("{}", x)); 会打印 1 2 3 吗？ 答案：什么都不打印。迭代器是惰性的，没有 collect / for_each 这类消费者，闭包根本不执行。改成 v.iter().for_each(|x| println!("{}", x));
19

用 clap 写一个命令行工具

用 clap 的 derive 写法：定义一个 struct，字段就是参数，#[derive(Parser)] 自动生成解析、校验和 --help。
$ cargo new greet && cd greet
$ cargo add clap --features derive

use clap::Parser;

/// 向某人打招呼
#[derive(Parser)]
struct Args {
    /// 名字
    name: String,                          // 位置参数（必填）
    /// 打招呼的次数
    #[arg(short, long, default_value_t = 1)]
    count: u8,                             // -c / --count，默认 1
}

fn main() {
    let args = Args::parse();
    for _ in 0..args.count {
        println!("Hello, {}!", args.name);
    }
}

$ cargo run -- Rust -c 2     # Hello, Rust! 打印两遍
$ cargo run -- --help        # 文档注释 /// 自动变成帮助文字
  • 不传 name 会报错 the following required arguments were not provided，校验 clap 帮你做了。
  • count: u8 传 -c abc 会自动报类型错误；想让参数可选就用 Option<T>（第 12 课）。
考考你：count 是 u8，运行 greet Ann -c 300 会怎样？ 答案：报错退出：300 is not in 0..=255。u8 最大 255，clap 解析时就拦下了。
20

用 Rust 调 HTTP API（reqwest + serde）

reqwest 发请求，serde 把返回的 JSON 直接变成你定义的 struct；只声明你需要的字段，其他的自动忽略。
$ cargo add reqwest --features blocking,json
$ cargo add serde --features derive

use serde::Deserialize;

#[derive(Deserialize, Debug)]
struct Repo {
    full_name: String,
    stargazers_count: u64,   // 字段名和 JSON 的 key 对上
}

fn main() -> Result<(), reqwest::Error> {
    let client = reqwest::blocking::Client::new();
    let repo: Repo = client
        .get("https://api.github.com/repos/rust-lang/rust")
        .header("User-Agent", "rust-demo")   // GitHub API 要求带 User-Agent
        .send()?                             // 第 13 课的 ?
        .json()?;                            // JSON → Repo
    println!("{} ⭐ {}", repo.full_name, repo.stargazers_count);
    Ok(())
}
  • blocking 写法最简单；正式服务一般用异步版：reqwest::get(...).await 配合 tokio（见学习路径阶段 4）。
  • JSON 里可能没有的字段，类型写成 Option<T>，缺了就是 None 而不是报错。
考考你：把字段改名成 stars: u64（JSON 里的 key 还是 stargazers_count），.json() 会得到什么？ 答案：Err：missing field `stars`。字段名必须和 key 对上，或者加 #[serde(rename = "stargazers_count")]。

系统学习 Rust 的路径

按每天 1 小时算，8 周能独立写小工具，之后按方向深入。每个阶段都有「检验标准」：做到了再往下走。

阶段 1 · 语法和所有权第 1–2 周 · 对应第 1–9 课
学什么变量、类型、函数、控制流；所有权三规则、Move/Clone/Copy、借用规则、String 与 &str。 读《The Rust Programming Language》（官方书，中文版《Rust 程序设计语言》）第 1–4、8 章。 练Rustlings（官方练习，一个个修好编译错误）：variables → functions → if → move_semantics → strings。 检验看到 E0382、E0502，能说出原因并改对。
阶段 2 · 建模、错误处理、工程化第 3–4 周 · 对应第 10–14 课
学什么struct/impl、enum/match、Option、Result 与 ?、Cargo、模块、单元测试。 读官方书第 5–7、9、11 章；《Rust by Example》对应章节（边看边跑）。 练Rustlings 的 structs、enums、options、error_handling、tests。 小项目命令行记账本：读写一个文本文件，用 enum 表示收入/支出，所有错误用 Result 返回，写 3 个测试。 检验整个项目里不出现 unwrap（测试除外）。
阶段 3 · 抽象和函数式第 5–6 周 · 对应第 15–18 课
学什么trait、泛型与约束、生命周期、迭代器与闭包、常用集合（Vec、HashMap）。 读官方书第 10、13 章；标准库文档里 Iterator 的方法列表（filter、map、fold、zip、enumerate）。 练Exercism 的 Rust 赛道（有导师点评）；把阶段 2 的项目里的 for 循环改写成迭代器链。 检验能给自己的类型实现 Display 和一个自定义 trait；能读懂带生命周期的函数签名。
阶段 4 · 实战：命令行与网络第 7–8 周 · 对应第 19–20 课
学什么clap 命令行、serde 序列化、reqwest 调 API；异步入门（async/await + tokio）。 读clap、serde、reqwest 的 docs.rs 文档首页示例；Tokio 官方教程（tokio.rs/tokio/tutorial）。 小项目GitHub 仓库查询工具：repo-cli rust-lang/rust 输出 star 数和最近 5 个 issue；加 --json 参数输出原始 JSON；先写 blocking 版，再改成 tokio 异步版。 检验项目通过 cargo clippy 无警告，有 README，发到 GitHub。
阶段 5 · 按方向进阶第 9 周以后
共同必修智能指针（Box、Rc、RefCell）、并发（线程、Arc<Mutex<T>>、channel）：官方书第 15、16 章。 后端服务axum + tokio + sqlx，写一个带数据库的 REST API。 AI 工程用 Rust 写高性能的数据处理或推理服务；用 PyO3 给 Python 写扩展。 系统/底层《Rust Atomics and Locks》（并发底层）、unsafe 和 FFI（The Rustonomicon）。 深入理解《Rust for Rustaceans》（中级进阶）；Google 的 Comprehensive Rust 课程（免费，适合复习查漏）。

学习方法

  • 先读报错。Rust 的报错会告诉你哪里错、为什么、怎么改。用 rustc --explain E0xxx 看完整解释。
  • 装好工具：rust-analyzer（编辑器插件，实时提示类型）、cargo fmt（自动格式化）、cargo clippy（代码建议，能学到地道写法）。
  • 先能跑，再优化。刚开始被借用检查卡住时，.clone() 一下没关系，先把功能做完，回头再去掉多余的 clone。
  • 每周做一个小东西。看十遍不如写一遍，项目比刷题更能暴露你没懂的地方。
